[SIZE="5"][B][COLOR="#0099CC"]For Users — What is AROMA-Next?[/COLOR][/B][/SIZE]
Remember the classic [B]AROMA Installer[/B] touch wizards inside TWRP? On modern phones (`arm64-v8a`, DRM/KMS displays, Android 10–16+ EROFS & Dynamic Partitions), the original 2013 binary froze recoveries, missed touchscreens, or couldn't modify read-only system partitions.

[B]AROMA-Next-Installer[/B] brings the full touch-driven experience safely back:
[LIST]
[*][B][COLOR="#0099CC"]Works on Modern Phones & Recoveries:[/COLOR][/B] Native `arm64-v8a` & `armeabi-v7a` support with both `DRM/KMS` (including Atomic KMS & inherited recovery FDs like OrangeFox / TWRP) and `fbdev` displays.
[*][B][COLOR="#0099CC"]Accurate Touch on High-Hz OLED Screens:[/COLOR][/B] Supports `/dev/input/event0..63` and Linux Multitouch Protocol Type-B.
[*][B][COLOR="#00AA55"]Safe by Design (Zero Recovery Hangs):[/COLOR][/B] Cleanly pauses/resumes recovery and restores its display on exit; if a recovery locks the screen without a fallback, AROMA-Next exits cleanly (`EXIT 77`) and runs the standard text installer instead of freezing.
[*][B][COLOR="#E67E22"]Smart Startup Environment Check:[/COLOR][/B] Automatically detects [B]Magisk[/B], [B]KernelSU / APatch[/B], or [B]RO2RW / SystemRW[/B] partitions at launch and alerts you immediately if no writable modding target is available.
[*][B][COLOR="#00AA55"]Flash Anywhere (Recovery OR Root App):[/COLOR][/B] Use the full Touch GUI inside TWRP/OrangeFox, or flash the exact same ZIP directly inside the Magisk / KernelSU / APatch app (automatic headless fallback).
[*][B][COLOR="#9B59B6"]Built-in Live Theme Switcher (New!):[/COLOR][/B] Ships with Miustone's crisp [B]Black & White[/B] OLED theme (custom 9-patch progress bar & monochrome icon set) as default — open [B]3-Dot Menu → Select Theme[/B] at any step to preview & switch themes live ([I]Black & White, ICS, MIUI 4, MIUI, Touchwiz, Franzyroy, Generic[/I]) without losing your current selections or restarting the installer.
[*][B][COLOR="#0099CC"]Reliable Hardware Key & Screenshot Combo:[/COLOR][/B] Volume/Power navigation no longer triggers accidental menu/button clicks during [B]Vol-Down + Power[/B] screenshots, complete with a crisp visual shutter flash when capturing `.bmp` screenshots.
[/LIST]

[SIZE="4"][B][COLOR="#0099CC"]1. Dual-Mode Systemless & Optional Pre-RW Template (`magisk-template/`)[/COLOR][/B][/SIZE]
Modern Android (`/system`, `/vendor`, `/product`, `/system_ext`) uses read-only [B]EROFS[/B] or deduplicated `shared_blocks` `ext4` with `dm-verity`. `AROMA-Next-Magisk-Template.zip` solves this cleanly:
[LIST]
[*][B][COLOR="#00AA55"]Systemless Mode (Default):[/COLOR][/B] Outputs a standard Magisk / KernelSU / APatch overlay module (`$MODPATH`, or directly `/data/adb/modules/<id>` via the built-in standalone recovery installer). Works on EROFS & active `dm-verity` with zero bootloop risk.
[*][B][COLOR="#E67E22"]Direct RW Mode (Optional):[/COLOR][/B] For partitions pre-converted with `RO2RW` / `SystemRW` and rebooted beforehand (`aroma_probe_rw()` checks real writability first and falls back to Systemless if read-only).
[/LIST]

[B]Key files in `magisk-template/`:[/B]
[LIST]
[*]`META-INF/com/google/android/update-binary` — Universal `arm64`/`arm32` recovery & `BOOTMODE` dispatcher (falls back on exit code `77`).
[*]`META-INF/com/google/android/aroma-config` — Touch wizard writing choices to `/tmp/aroma/*.prop`.
[*]`META-INF/com/google/android/aroma-env-check.sh` — Probes `/data/adb` (Magisk/KSU/APatch) & RW partitions into `/tmp/aroma/env.prop`.
[*]`META-INF/com/google/android/aroma-mod-lib.sh` — Helper API for `customize.sh`:
  [CODE]aroma_mod_init "$REQ_MODE" "$MODPATH" 1
aroma_mod_edit_prop "ro.config.media_vol_steps" "30"
aroma_mod_copy "$MODPATH/files/my.conf" "system/etc/my.conf" 0644
aroma_mod_delete "system/app/ExampleBloat" "dir"
aroma_mod_patch_file "system/etc/hosts" "s/old/new/"[/CODE]
[*]`META-INF/com/google/android/magisk-installer` & `customize.sh` — Bridges Touch selections to module install (`util_functions.sh` or standalone `/data/adb/modules`).
[/LIST]

[SIZE="4"][B][COLOR="#0099CC"]2. Engine & Port Highlights (vs. Upstream 2013 Base)[/COLOR][/B][/SIZE]
[LIST]
[*][B]64-bit Cleanliness:[/B] Replaced 32-bit pointer truncations with `uintptr_t`/`intptr_t` (`aroma_memory.c`, `aroma_graph.c`, `Zip.c`), fixed `AARRAY_ITEM` sizing, `0755` octal permissions, C11 inline linkage, and ARM64 NEON 32-bit blitter alpha initialization (`blt_neon.c`).
[*][B]DRM/KMS & Atomic Backend (`src/libs/graph_drm.c`):[/B] Zero `libdrm.so` dependency; inherits DRM master FDs via `/proc/self/fd`, drives Atomic KMS double-buffered dumb buffers, handles Exynos/Tensor `RGBA8888` byte ordering, disables/restores recovery overlay planes cleanly before `RMFB`, and falls back to `SETCRTC` + `DIRTYFB` / `fbdev`.
[*][B]Input & Process Control:[/B] `INDR_MAXDEV = 64`, Protocol Type-B `ABS_MT_SLOT`, `BTN_TOUCH` release handling, LED vibrator fallback, ancestor `SIGSTOP`/`SIGCONT` chain in `aroma.c`, and pre-`viewbox()` font/theme readiness for dialogs.
[/LIST]
