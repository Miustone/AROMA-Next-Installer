[CENTER][SIZE="6"][B]AROMA-Next Installer[/B][/SIZE]
[SIZE="3"]Modern [B]arm64-v8a[/B] & [B]armeabi-v7a[/B] port of AROMA Installer with DRM/KMS + fbdev support, Type-B Multitouch & Magisk/KernelSU Dual-Mode[/SIZE][/CENTER]

[HR][/HR]

[SIZE="4"][B]Why AROMA-Next?[/B][/SIZE]
Ahmad Amarullah's original [URL="https://github.com/amarullz/AROMA-Installer"]AROMA Installer[/URL] has been broken on modern smartphones and custom recoveries for years. Contrary to common rumors, the problem was not Toolbox/Toybox — AROMA is a standalone statically-linked C binary that failed on modern devices due to:
[LIST]
[*]32-bit-only ARM builds (`armeabi-v7a`) and 64-bit pointer truncation bugs on `arm64-v8a` devices
[*]Hardcoded `/dev/graphics/fb0` (`fbdev`) graphics without DRM/KMS support or real `fb_var_screeninfo` channel offsets
[*]Input device scanner capped at 15 `/dev/input/event*` nodes (`INDR_MAXDEV = 15`), missing touchscreens on `event15+`
[*]Broken Linux Multitouch Protocol Type-B (`ABS_MT_SLOT`) handling and shared static touch globals
[*]Hanging/freezing TWRP if display initialization failed while the parent recovery process was `SIGSTOP`ped
[/LIST]

[B]AROMA-Next Installer[/B] modernizes the C codebase so ROM, kernel, and Magisk/KernelSU module developers can ship [B]one universal flashable ZIP[/B] with Touch GUI in recovery and clean app-mode installation in Android.

[HR][/HR]

[SIZE="4"][B]Key Features & Changes[/B][/SIZE]
[LIST]
[*][B]Native 64-bit (`arm64-v8a`) + 32-bit (`armeabi-v7a`) Support:[/B] Fixed 64-bit pointer truncation (`uintptr_t`), C11 inline linkage, allocation bugs, and NEON intrinsics; compiles cleanly with Android NDK r27c and Zig `cc`.
[*][B]Dual Display Backend (`fbdev` + Pure-ioctl `DRM/KMS`):[/B]
  [LIST]
  [*]Supports `/dev/graphics/fb0` & `/dev/fb0` with proper `red/green/blue/transp` channel offsets and `MAP_FAILED` validation.
  [*]Includes a zero-dependency Linux kernel-ioctl DRM/KMS dumb-buffer backend (`/dev/dri/card0..3`, `DRM_IOCTL_MODE_SETCRTC` + `DIRTYFB` flush for command-mode OLED panels).
  [*]Auto-detects available backend (or override via `AROMA_DISPLAY=drm` / `fbdev`).
  [/LIST]
[*][B]Anti-Freeze Recovery Safety (`EXIT 77`):[/B] If neither `fbdev` nor DRM master can be acquired (see [I]Known Limitations[/I] below), AROMA-Next immediately resumes the parent recovery (`SIGCONT`) and exits with code `77` so the universal dispatcher runs the non-GUI fallback instead of freezing TWRP.
[*][B]Modern Touch & Haptics:[/B]
  [LIST]
  [*]Raised `INDR_MAXDEV` from `15` to `64` for modern `/dev/input/event*` layouts.
  [*]Added `ABS_MT_SLOT` (Protocol Type-B) filtering so multi-finger touches do not corrupt slot-0 UI coordinates.
  [*]Added `BTN_TOUCH` release handling, `ABS_X`/`ABS_Y` calibration fallback, and `/sys/class/leds/vibrator/{duration,activate}` haptic fallback.
  [/LIST]
[*][B]Universal Recovery + Magisk / KernelSU / APatch Dual-Mode & Systemless File Modder:[/B]
  [LIST]
  [*][B]In Custom Recovery (`BOOTMODE=false`):[/B] Auto-detects `uname -m` (`aarch64` vs `armv7l`), launches the Touch GUI, saves user selections to `/tmp/aroma/*.prop`, and executes either `update-binary-installer` or `magisk-installer` (`customize.sh`).
  [*][B]In Magisk / KernelSU / APatch App (`BOOTMODE=true`):[/B] Automatically skips the recovery GUI (since Android SurfaceFlinger owns the display) and runs the module's `customize.sh` with defaults/headless fallback.
  [*][B]Systemless-First Modding (`aroma-mod-lib.sh`):[/B] Brings back classic AROMA-style file copy/replace, debloat/delete (`.replace` & KernelSU `0:0` whiteouts), `system.prop` tweaks, and file patching safely as a systemless overlay module — works on EROFS, `shared_blocks` ext4, Virtual A/B, and active `dm-verity` with zero bootloop risk.
  [*][B]Optional Direct RW Mode (`RO2RW` / `SystemRW`):[/B] Power users who pre-converted partitions to RW beforehand (and rebooted) can select Direct RW Mode in the wizard; AROMA-Next probes actual partition writability first and safely falls back to Systemless if partitions are still EROFS/RO.
  [/LIST]
[*][B]Modern Recovery Compatibility:[/B] Dynamic `mount`/`umount` binary lookup (`/sbin`, `/system/bin`, `/bin`, `/vendor/bin`) instead of hardcoded `/sbin/mount`.
[/LIST]

[SIZE="4"][B]Known Limitations & Call for Testers[/B][/SIZE]
[B]Important technical note on DRM-based TWRP / OrangeFox builds:[/B]
On modern recoveries that use DRM/KMS and keep [B]DRM Master[/B] open while executing an `update-binary` child process, `SIGSTOP` pauses the recovery without calling `drmDropMaster()`. In that scenario, any child binary attempting `DRM_IOCTL_SET_MASTER` will receive `EBUSY`/`EACCES` unless the recovery itself releases DRM master.
On recoveries that still expose `fbdev` or release DRM master, the Touch GUI renders directly. On recoveries that lock DRM master, AROMA-Next now [B]exits cleanly with code 77 and triggers the fallback installer[/B] instead of hanging your device.

[I]Testing feedback from different devices, TWRP/OrangeFox builds, and Magisk/KernelSU setups is very welcome! Please include `/tmp/recovery.log` if you report an issue.[/I]

[SIZE="4"][B]For Developers / Module Authors[/B][/SIZE]
Check out the included `magisk-template/` folder in the repository:
[LIST]
[*][B]`META-INF/com/google/android/update-binary`[/B] — Universal `arm64`/`arm32` Recovery & Magisk/KernelSU dispatcher
[*][B]`META-INF/com/google/android/aroma-config`[/B] — Your Touch GUI wizard (writes selections to `/tmp/aroma/*.prop`)
[*][B]`META-INF/com/google/android/magisk-installer`[/B] — Bridges AROMA into Magisk's `util_functions.sh` / `install_module`
[*][B]`customize.sh`[/B] — Reads `${AROMA_TMP:-/tmp/aroma}/*.prop` in Recovery mode or falls back to defaults in App mode
[/LIST]

python build.py --arch arm64 arm32
